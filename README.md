# a2n

> **a2n = Apple 2 NetEase**（仓库名 `apple2netease`，命令名 `a2n`）

自用音乐 app 歌单转换工具。把本机「音乐」App（Apple Music）的歌单，转换并导入到网易云音乐。

没有现成的一键方案（详见文末「为什么没有现成工具」），于是自己做了一条。

## 它解决什么问题

Apple Music 和网易云音乐之间**没有官方互通方案**，第三方迁移服务也不支持国内平台。
本工具把你「音乐」App 里已有的歌单，按歌名/歌手/专辑/时长做模糊匹配，在网易云音乐里**新建**一个对应歌单。

## 三步用法

**不需要导出 XML。** 直接读本机「音乐」App 的资料库。

### 第 1 步：看有哪些歌单

```bash
cd ~/Desktop/apple2netease
./a2n list
```

直接通过 AppleScript 读 Music.app。实测 3600+ 首整个资料库 **1 秒内**读完 ——
做法是每个歌单一次性取「全部歌名/歌手/专辑/时长」四个列表（各一次 Apple 事件），
而不是逐首查属性。系统歌单（资料库、音乐、音乐视频…）会被标出并默认跳过。

> 首次运行若报权限错误，去 **系统设置 → 隐私与安全性 → 自动化**，允许控制「音乐」。

### 第 2 步：先干跑一遍看匹配率

```bash
./a2n run --dry-run
```

这一步 **不写你的网易云账号**，只做搜索匹配，输出命中情况，并在
`reports/<歌单名>.csv` 写好详细报告。

### 第 3 步：正式导入

```bash
./a2n login          # 先登录（见下）
./a2n run            # 匹配 + 建歌单 + 加曲
```

只想导一个歌单：

```bash
./a2n run --playlist "喜爱歌曲"
```

## 登录

两种方式，任选：

```bash
./a2n login                              # 扫码：弹出二维码图片，用网易云 App 扫
./a2n login --sms-send 13800138000       # 短信：发验证码到手机
./a2n login --sms-code 13800138000 6514  # 用收到的验证码完成登录
```

登录后 cookie 存到 `.a2n_cookies.json`（权限 600，只有你能读），有效期通常几个月。

> 二维码每张只有几分钟有效期。工具会**自动换新码**并重新弹窗（总共等 15 分钟），
> 所以看到「已失效」不用重跑命令，直接扫最新弹出的那张即可。

## 命令一览

| 命令 | 作用 |
|---|---|
| `./a2n list [xml]` | 列出歌单和曲目数（省略 xml 则直接读 Music.app） |
| `./a2n login` | 扫码登录；`--sms-send` / `--sms-code` 走短信 |
| `./a2n run [xml]` | 匹配 + 导入 |
| `./a2n run --dry-run` | 只匹配、只出报告，不动网易云 |
| `./a2n run --playlist "名称"` | 只处理指定歌单（支持模糊匹配） |
| `./a2n run --limit 20` | 每个歌单最多处理 20 首（试跑用） |
| `./a2n run --threshold 0.8` | 调高匹配阈值（更严，误配更少） |
| `./a2n run --delay 1.0` | 手动放慢请求间隔 |
| `./a2n run --yes` | 不再逐个确认 |
| `./a2n run --all` | 连系统歌单（资料库、最近添加…）也一起处理 |
| `./a2n run --anon` | 跳过登录（不推荐，见下） |

`[xml]` 参数仍然支持，想用导出的资料库 XML 就把它传进去。

## 实测性能

### 全库实测（3623 首，2026-10-26）

| | 数字 |
|---|---|
| 处理曲目 | 3623 首 |
| 命中 | **3449 首（95.2%）** |
| 置信度不足 / 搜不到 | 168 / 6 |
| 实发请求 / 缓存命中 | 3672 / 1355 |
| 耗时 | **约 11 分钟** |
| 最终节流 | **0.10s（全程没被限流）** |

> 3449 条匹配只写进歌单 **3113 首**，少的 336 首是**源库里本来就有重复**
> （272 组，同一首歌出现在多张专辑/版本里），不是丢歌。

### 两代接口对比

| | 老接口 `/api/search/get/web` | 现在的 `/weapi/cloudsearch/get/web` |
|---|---|---|
| 33 首歌耗时 | **8 分 40 秒** | **17.6 秒** |
| 单请求耗时 | 0.2 秒（但多数被拒） | 约 0.4 秒 |
| 固定间隔 1 秒成功率 | 0/12 | 12/12 |
| 固定间隔 3 秒成功率 | 0/14 | 12/12 |
| 节流值 | 一路涨到 5.82 秒 | 稳定在 0.10 秒 |

**关键在于接口而不是限流策略。** 老的 `/api/` 端点已被 WAF 拦死，返回 `code=405`，
且表现出「间隔越长成功率越低」的惩罚特性，登录也救不了。换成 `/weapi/` 加密通道后，
同样的请求稳定 200。

### 并发才是提速的关键

瓶颈是**网络往返（每请求约 0.4 秒）**，不是网易云的频率限制 —— 所以提高并发既快又安全：

```bash
./a2n run --playlist 资料库 --yes --delay 0.1 --jobs 6
```

`--jobs 6` 把吞吐从「喜爱歌曲实测 2 次/秒」提到 **15.5 次/秒（约 8 倍）**，
全库 11 分钟跑完，全程零 405。默认 `--jobs 1` 是保守值。

> ⚠️ 并发会拉高瞬时 QPS。若担心账号风险，用 `--jobs 3` 折中；
> 第一次试水建议先 `--dry-run --jobs 1` 看看命中率。

跑完会打印一行统计：`实发 N 次请求 / 缓存命中 M 次 / 最终节流 X.XXs`。

## 搜索缓存

搜索结果存在 `.a2n_cache.json`，重跑同一个歌单**不再发请求**（实测第二次跑实发 0 次请求）。
调阈值、改报告、重新导入都不会浪费额度。删掉这个文件即可强制重新搜索。

## 匹配是怎么判定的

每首歌用 3 组关键词搜索（`歌手 歌名`、`歌名 歌手`、`歌名`），对每个候选打分：

```
得分 = 0.58×歌名相似度 + 0.32×歌手相似度 + 0.10×专辑相似度
     + 时长奖励（差 ≤2 秒 +0.10，≤5 秒 +0.04，差 >20 秒 -0.15）
     - 版本惩罚（候选是伴奏/翻唱/remix 而源不是，-0.20）
```

歌名或歌手存在包含关系时会直接拉到 0.90 以上。得分 ≥ `--threshold`（默认 **0.70**）才算命中。
歌名和歌手都完全一致时得 1.00，此时不再浪费请求试其它关键词。

归一化会忽略大小写、全角半角、括号内容（`(Live)`、`【remix】`）和 `feat./ft.` 后缀。

## 报告里会写什么

`reports/<歌单名>.csv`（UTF-8-BOM，Excel 直接打开）列出每首歌的状态：

- **OK** —— 已匹配，会写进歌单
- **置信度不足** —— 找到了候选但分数不够，`说明` 列会告诉你原因（比如「只搜到翻唱/伴奏版，原唱可能无版权」）
- **未找到** —— 网易云根本搜不到

后两类都会把最接近的候选一并写进去，方便你人工核对后手动补。手动补的曲目不会被自动导入。

## 技术要点：weapi 加密

网易云的 `/weapi/` 接口要求参数加密，否则一律返回 `401 无权限访问. ENC`：

```
JSON → AES-128-CBC(NONCE=0CoJUm6Qyw8W8jud) → base64
     → AES-128-CBC(随机16位密钥) → base64  = params
随机16位密钥倒序后做裸 RSA（modulus + e=0x10001）= encSecKey
```

实现见 `a2n.py` 的 `weapi()` / `_aes_b64()` / `_rsa_encrypt()`。
AES 借道系统 `openssl enc -aes-128-cbc`，**不引入任何新依赖**。

## 常见问题

**Q：某个歌手的歌全部匹配不上？**
多半是版权问题。比如周杰伦的曲库在网易云没有授权，搜 `周杰伦 晴天` 返回的全是翻唱 ——
这时候工具会正确地拒绝匹配并告诉你是翻唱，而不是给你加一首错的。这类只能手动处理。

**Q：导入后曲目数比报告里的少？**
源歌单里有重复曲目。同一个网易云 ID 被加两次，网易云会去重。
（实测 32 条匹配 → 30 首唯一，少的 2 首是 `After Hours` 和 `From The Start` 各有两条重复。）

**Q：`--anon` 匿名行不行？**
不建议。实测未登录时请求会被严厉惩罚，且惩罚会持续很久。

**Q：`list` 里没看到某个歌单？**
可能是系统歌单被默认跳过了（输出里会有标注），加 `--all` 试试；也可能是空歌单，会被忽略。

**Q：导入会覆盖我现有的歌单吗？**
不会。永远是**新建**歌单；如果同名歌单已存在，会新建一个叫 `xxx (导入)` 的。

**Q：cookie 存哪了？会不会泄露？**
`.a2n_cookies.json`，就在这个目录里，文件权限 600（只有你能读）。
手机号只用于本地调用网易云自己的短信接口，不会外传。

## 为什么没有现成工具

调研结论（2026-10）：

- **TuneMyMusic / Soundiiz / FreeYourMusic 这类迁移服务都不支持网易云** —— 扒了 TuneMyMusic 的
  完整 sitemap（393 个页面），支持的 17 个平台清一色是欧美系（Apple Music、Spotify、Tidal、
  Deezer、KKBOX、YouTube Music…），没有任何国内平台。
- **GitHub 上名字最像的项目是空壳** —— `wangxd8604/from-apple-music-to-netease-cloudmusic`
  只有一个 3KB 的 notebook，做到「读 iTunes XML → 正则抠出歌名歌手 → 存 Excel」就没了。
- **`kekevow0-cpu/netease-playlist-importer`** 是能用的写入端，但它读的是 Windows 客户端
  cookie（源码里有 `ctypes.wintypes`、`sys.platform != "win32"` 直接抛错），Mac 用不了。
- 苹果不开放「读取用户歌单」的 API，网易云的「导入外部歌单」也只支持国内平台，
  所以商业工具不会做这个方向。

本项目借用了上述思路，但数据源走 **AppleScript 直读 Music.app**、登录走 **扫码或短信**、
请求走 **weapi 加密通道**，因此**不需要 Windows 客户端，也不需要 iTunes**。
